# ギアライン 仕様

ゲームの規則と技術的な仕様をまとめます。数値は `src/main.asm` と `tools/gen.py` の定義に基づきます。

## 時間の単位

シミュレーションは「パス」単位で進みます。1パスはマップ全体（1024マス）を1回走査することで、1フレームに64マスずつ処理するため16フレームかかります（約0.27秒）。メニューやサブ画面を開いている間も、シミュレーションとプレイ時間は進み続けます。

## ゲームの流れ

- 起動するとタイトル画面になります。セーブデータがあれば「つづきから」が表示され、初期選択になります。
- 「はじめから」を選ぶと、マップがランダムに生成されます。初期在庫は鉄板40と石12です。
- 10個目の目標を達成すると、ロケット発射の演出とエンディングが表示されます。その後もゲームは続けられます。
- モノクロのゲームボーイでは「ゲームボーイカラー せんようです」と表示して停止します。

## マップ

- 大きさは32×32マスです。画面には20×16マスが表示され、カーソルの位置に合わせてスクロールします。
- 外周は水です。2×2のハブが中央の(15,15)-(16,16)に固定で置かれます。
- 地形は、草、木、水、鉱石（鉄鉱石・銅鉱石・石炭・石）です。木と水の上には建設できません。
- 鉱石は無限で、掘っても減りません。
- マップを生成するときは、乱数で木・池・鉱床を配置します。鉱床の大まかな位置は固定です。

| 鉱石 | 鉱床の数 |
|---|---|
| 鉄鉱石 | 4 |
| 銅鉱石 | 3 |
| 石炭 | 3 |
| 石 | 2 |

## 建物

解放条件は、達成済みの目標の数です。撤去すると建設コストは全額戻りますが、機械の中にある品物は失われます。ベルト上の品物は在庫に戻ります。

| 建物 | コスト | 解放 | 機能 | 電力 |
|---|---|---|---|---|
| ベルト | 鉄板1 | 最初から | 向いている方向へ1パスに1マス運ぶ。1マスに1個まで。正面からは受け取らない | – |
| マイナー | 鉄板4 | 最初から | 鉱石の上に置く。8パスに1個掘り出す | – |
| かまど | 石4 | 最初から | 鉄鉱石→鉄板、銅鉱石→銅板、石→レンガ。8パスに1個 | – |
| 組立機 | 鉄板6＋銅板4 | 1 | 選んだレシピで加工する | 消費2 |
| 発電機 | 鉄板6＋レンガ4 | 1 | 石炭1個で33パスのあいだ発電する | 供給8 |
| 分配機 | 鉄板2＋歯車2 | 2 | 受け取った品物を前・右・左の順に振り分ける。詰まっている出口は飛ばす | – |
| 立体交差 | 鉄板2＋歯車2 | 2 | 縦と横の流れを交差させる。入ってきた方向へまっすぐ出す | – |
| 高速ドリル | 鋼材4＋回路2 | 5 | 鉱石の上に置く。3パスに1個掘り出す | 消費3 |
| 電気かまど | 鋼材4＋レンガ6 | 5 | かまどと同じ加工を3パスに1個で行う | 消費3 |
| ハブ | – | 最初から配置済み | 届いた品物を在庫に加える（各品目の上限は9999）。撤去できない | – |

- 機械は、向きのしるしの方向にある隣のマスへ品物を出します。隣がベルトでなくても、受け取れる機械やハブなら直接渡します。
- かまどは、同じ種類の材料を4個まで溜めておけます。組立機は材料ごとに6個まで溜めておけます。
- マイナー、高速ドリル、組立機は、出した品物が受け取られずに一定数たまると止まります。

## レシピ（組立機）

組立機を置いたとき、または組立機の上でAを押したときにレシピを選べます。レシピを変えると、中にある材料と完成品は失われます。

| 出力 | 入力 | 時間（パス） | 解放 |
|---|---|---|---|
| 歯車1 | 鉄板2 | 6 | 1 |
| 銅線2 | 銅板1 | 4 | 2 |
| 回路1 | 鉄板1＋銅線3 | 12 | 3 |
| 鋼材1 | 鉄板2＋石炭1 | 12 | 4 |
| エンジン1 | 歯車2＋鋼材1 | 20 | 6 |
| フレーム1 | 鋼材1＋レンガ2 | 16 | 6 |
| 電子頭脳1 | 回路2＋銅線2 | 24 | 7 |
| ロケット部品1 | エンジン1＋電子頭脳1 | 32 | 8 |

## 電力

- 需要は、置かれている組立機・高速ドリル・電気かまどの消費量の合計です。止まっている機械の分も含みます。
- 供給は、燃焼中の発電機1台につき8です。発電機は燃料が切れたとき、需要があれば石炭を1個消費して再び燃焼します。需要がなければ点火しません。
- 供給が需要に足りないと、電力を使う機械は一部のパスで休むようになり、処理が遅くなります。発電機がなくても、ごく遅い速度で動き続けます。
- 画面下のHUDに「電 需要/供給」が表示され、電力が足りないパスでは「!」が付きます。

## 操作の詳細

| 入力 | 動作 |
|---|---|
| 十字キー | カーソル移動（押し続けるとリピート） |
| A | 空きマスに選んだ建物を建てる。組立機の上ではレシピを選ぶ。ベルト選択中に既存のベルトの上で押すと、向きを変える（無料） |
| Aを押したまま移動 | 移動先に続けて建てる。ベルトは移動方向に向きがそろう |
| B | カーソル位置の建物を撤去 |
| Bを押したまま移動 | 続けて撤去 |
| SELECT | 建てる向きを時計回りに回す |
| START | メニューを開く |

メニューには、解放済みの建物（コスト付き）、目標を見る、ざいこを見る、セーブする、おんがく ON/OFF、あそびかた が並びます。

## サウンド

- BGMは1曲で、メニューからON/OFFを切り替えられます。この設定もセーブされます。
- 設置、撤去、カーソル移動、エラー、目標の達成と通知で効果音が鳴ります。効果音はBGMがOFFでも鳴ります。

## 既知の挙動

生成されたときの仕様を保つため、次の点は修正していません。

- ゲーム内の「あそびかた」では、機械は黄色いしるしの方向へ品物を出すと説明されています。ただし高速ドリルのしるしは白、かまどと電気かまどのしるしは炎の色で表示されます。
- 「あそびかた」では組立機に電力が必要と説明されていますが、発電機がなくても遅い速度で動きます。
- 止まっている機械（レシピ未設定の組立機、出力が詰まったドリルなど）も電力の需要に含まれます。そのため、需要がある限り発電機は石炭を消費し続けます。
- 石炭1個の燃焼時間は33パスです。
- メニューやサブ画面を開いている間も、シミュレーションは止まりません。
- 「はじめから」を選んでも既存のセーブデータはすぐには消えませんが、次のセーブで確認なしに上書きされます。
- HUDの電力表示は3桁です。1000以上になると上の桁が表示されません。
- プレイ時間は60フレームを1秒として数えるため、実際の時間より少し遅れます。99時間に達した後は、時間の桁が増えずに分の桁だけが0に戻ります。

## 技術仕様

| 項目 | 値 |
|---|---|
| 対応機種 | ゲームボーイカラー専用（ヘッダー $0143=$C0） |
| カートリッジ | MBC5+RAM+BATTERY、ROM 32KB、SRAM 8KB |
| CPU | 倍速モードを使う |
| 割り込み | VBlankのみ |
| フォント | 美咲フォント（8×8）。使う文字だけを抜き出してVRAMバンク1に置く（最大254字） |

### メモリ配置

| 領域 | 内容 |
|---|---|
| WRAM0 $C000-$CFFF | マップの4枚の配列（地形・建物の種類と向き・アイテム・データ）。各1024バイトで、添字は y*32+x |
| WRAMX1 $D000-$D7FF | 機械の状態バッファ2枚（各1024バイト） |
| WRAMX1 $D800- | ゲーム変数。$DE00 に OAM バッファ |

### セーブデータ

| SRAMアドレス | 内容 |
|---|---|
| $A000-$A003 | マジック値 `GL01`（最後に書き込む） |
| $A004-$A041 | ゲーム変数（在庫、目標の進行、カーソル、電力の状態、プレイ時間、BGM設定、乱数の状態など） |
| $A100-$B0FF | マップの4枚の配列 |
| $B100-$B8FF | 機械の状態バッファ2枚 |

セーブデータの有無は、マジック値だけで判定します。チェックサムはありません。

### アセット生成

`tools/gen.py` は次のファイルを `build/` に生成します。

| ファイル | 内容 |
|---|---|
| `misakiUTF16FontData.h` | 取得したフォントデータ（SHA-256で検証） |
| `font.bin` | 使う文字だけのグリフ |
| `strings.inc` | 文字列、目標データ |
| `tiles.bin`, `tileattr.bin`, `gfx.inc` | タイル、タイルごとのパレット番号、タイル番号の定数 |
| `beltanim.bin` | ベルトのアニメーション |
| `pal.inc` | BG・OBJのパレット |
| `music.inc` | BGMのデータ |
